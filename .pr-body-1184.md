## What

Adds `LayerAPI.getStyle(id)`: one read of a layer's current effective style plus
per-dimension provenance, so a host can report "this layer looks like this, and
here is why" without re-deriving any of it.

## Changes

- `core/layer/type.ts` — `LayerStyleSnapshot` (+ `StyleProvenance`) and the
  optional `getStyle` slot on `LayerAPI`.
- `LayerControl/controller.ts` — `getStyle(id)`. Every value comes from the
  dimension registry `value()` readers the style panel already publishes, so
  the reader and the panel cannot disagree. Delegated layers
  (Heatmap/Measure) merge their `styleProvider()` output under the same
  keys, so a host sees one shape regardless of who owns the paint.
- `CHANGELOG.md` — one short line folded into the existing LayerControl entry.

Not included: JS reference documentation in `doc/source/api.rst` (docs cover
Python only for now).

## Public surface

```js
map.foliplus.LayerAPI.getStyle(layerId)
  -> { id, opacity, zoomRange, size, fill, border, icon, label, provenance } | null
```

`LayerController` implements `LayerAPI` directly (`this.map.foliplus.LayerAPI = this`),
so this is a one-line call. Returns `null` for an unknown id or a controller
that has not attached.
