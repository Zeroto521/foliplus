## What
Slice B of the ui-layer relocation: group the interactive overlay engines under `common/engine/`.

- Move `dropdown.ts`, `listbox.ts`, `schemePicker.ts`, `form.ts`, `placement.ts`, `portalRoot.ts` from `foliplus/js/common/` into `foliplus/js/common/engine/` (git mv + consumer import updates, ~35 imports).
- Build scripts: `scan-registry.mjs` now recursively discovers `common/` subdirectories and registers each module on the flat shared namespace (`window.foliplus.common["<name>"]`); `global-namespace-plugin.mjs` `runtimeTarget` takes the last path segment (`common/<sub>/<name>` → `common.<name>`); a same-name guard throws if two subdirectory modules would collide on the flat key.
- Track the bare-`addEventListener` listener-guard allow-list across the move (`common/dropdown.ts` / `common/listbox.ts` → `common/engine/...`).

## Why
These are stateful, event-driven, Leaflet/portal-aware engines, so they do not meet the eta `ui/` admission criteria (pure DOM builders). They stay under `common/` but are grouped into `common/engine/` to keep the shared surface readable. The change is behavior-preserving: global keys stay `foliplus.common.dropdown` etc., and the build output is byte-identical to the flat layout (differences are only the git-version string, module path segments, and module ordering).
