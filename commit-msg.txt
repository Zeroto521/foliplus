refactor(LayerControl): fold rename and hidden-visibility into one `applyUserState`

applyNamesState() and applyHiddenState() are two halves of the same
projections-onto-user-state model, so they are now one pass:

- `applyUserState(id?)` sweeps `hiddenIds` and `renamedNames` together and
  shares one stale-id pruning. The full sweep no longer needs two calls.
- The registry half of a hide is split into `applyHiddenStateOne()` so the
  targeted path can project a layer before its row is rendered, while
  `applyHiddenOne()` owns the row sync.
- Both targeted projections are membership-guarded. `insertLayerItem()` calls
  this once per late registration, including layers the user never touched,
  so an unhidden layer must not be hidden and a missing rename must not write
  `undefined` over the registry name. Without the guard every third-party
  registration was force-hidden on arrival.

Also fixes a test that focused an id it never registered: `heatmap1` was never
added to the registry, so `focusLayer()` returned early and the assertions
passed vacuously.
